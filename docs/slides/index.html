Architect Refuse

The no is part of the product. Apply and Refuse share one door.

The failure

An agent with no path invents a file.

You ask for a small fix on the login screen and never name the file. The answer comes back almost sure, and it edits a file that was not in the project.

One door

architect-gate

The button on Architect Refuse and the agent in chat both call the same defineAction. Same rule. Same receipt. Locate, then diagnose, then Apply or Refuse.

The rule

What the door allows.

InputDecision
Empty locate, or no pathRefuse
Secrets, destructive SQL, force-pushRefuse
Confidence under 0.4Refuse
A clear path, safe risk, confidence at least 0.4Apply, and only that path

Three requests, one page

Refuse — empty Locate No path

Refuse: empty Locate. Do not Apply without evidence. Confidence 0.9 does not invent a file.

Refuse — secrets risk Wrong file

Refuse: secrets is out of policy for unattended Apply. server/secrets.ts at 0.95 stays closed.

Apply — clear Locate Right size

Apply: Locate evidence is sufficient and risk is within policy. Next step names only actions/architect-gate.ts.

Same receipt

The button and the chat agree.

A yes has to arrive the same way as a no. No evidence, the answer is no. What you claim has to be on the Architect Refuse page.
